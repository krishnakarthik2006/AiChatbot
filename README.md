# Local AI Chatbot

This repository contains a private chatbot stack with a Flask backend, a React + Vite frontend, and an Ollama-only local LLM path. It now also includes a separate FastAPI Retrieval-Augmented Generation (RAG) service for document-grounded question answering.

## Overview

- The default engine is Ollama running on your machine.
- The frontend talks to `http://localhost:5000/api/chat`.
- Accounts, session ids, and conversation history are persisted in a local JSON store; no SQL server is required.
- The trained intent classifier can still provide metadata, but assistant replies are generated by Ollama only.
- The RAG API runs independently at `http://localhost:8000`, uses Groq Llama 3.3 70B for generation, and returns source citations.

## Features

- Real-time chat UI with a polished glass-panel layout.
- Custom intent model with TF-IDF + Logistic Regression.
- Session memory and conversation persistence.
- Required local LLM integration through Ollama.
- Multiple response modes: balanced, precise, and creative.
- Local-first privacy model with no cloud API keys or deployment modules required.
- ai_chatbot RAG pipeline: FastEmbed `all-MiniLM-L6-v2`, Chroma vector search, recursive 2,000-character chunks with 500-character overlap, and top-k semantic retrieval.
- Citation-aware, multilingual document responses with prompt-injection filtering.
- A 32-case automated evaluation suite for retrieval, robustness, hallucinations, document updates, contradictions, chunk boundaries, and security.

## Quick Start

Install dependencies:

```powershell
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
```

Train or refresh the custom intent model:

```powershell
.\.venv\Scripts\python.exe train_model.py
```

Start the Flask backend used by the web UI:

```powershell
.\.venv\Scripts\python.exe app.py
```

Start the React frontend in a second terminal:

```powershell
cd frontend
npm install
npm run dev
```

Open the browser UI at:

```text
http://localhost:5173
```

The Flask-rendered UI is also available at:

```text
http://localhost:5000
```

## ai_chatbot RAG API

The RAG service is intentionally separate from the existing authenticated Flask chatbot, allowing it to be evaluated and deployed independently without changing the legacy local-Ollama flow.

1. Add approved source material to `documents/`. Supported formats are PDF, Markdown, HTML, and text.
2. Add a Groq key to `.env`:

```env
GROQ_API_KEY=your-key
```

3. Start the API:

```powershell
.\.venv\Scripts\uvicorn.exe rag_api:app --reload --port 8000
```

4. Rebuild the index after adding or changing source material:

```powershell
Invoke-RestMethod -Method POST http://127.0.0.1:8000/api/documents/ingest
```

5. Ask a question:

```powershell
Invoke-RestMethod -Method POST http://127.0.0.1:8000/api/chat -ContentType 'application/json' -Body '{"message":"What are the hostel rules?"}'
```

Responses include an ordered `citations` array with the source name, chunk identifier, excerpt, and relevance score. The index rebuilds from scratch on ingestion, preventing stale chunks after document updates.

ChromaDB is connected locally by default. Its persistent directory and collection prefix can be configured in `.env`:

```env
CHROMA_PERSIST_DIRECTORY=./chroma_db
CHROMA_COLLECTION=ai_chatbot_knowledge_base
```

`GET http://127.0.0.1:8000/api/health` reports `rag.chroma.connected: true` when the persistent vector store is reachable.

### RAG workspace features

- Use **Documents** in the sidebar to upload, download, delete, re-index, summarize, or ask one document. Every uploaded document and index is isolated to its logged-in account.
- RAG settings include response-language choice and an opt-in cited web fallback. Web fallback uses DuckDuckGo only when selected; document sources remain the default.
- The chat supports streamed RAG output, cancellation, browser text-to-speech, conversation search/rename/export/delete, and light/dark themes.
- Set `RAG_ADMIN_EMAILS=email@example.com` in `.env` to show the admin panel for that account. It reports document activity, evaluation coverage, latency/confidence metrics, and user-marked failed responses.
- Image documents use OCR when the Tesseract desktop application is installed and available on `PATH`.

### Advanced AI capabilities

- **Hybrid retrieval and truth controls:** semantic and lexical retrieval are combined, citations retain source/version metadata, weak-retrieval queries are surfaced in analytics, and date-like conflicts in retrieved sources are flagged.
- **Multimodal knowledge:** PDFs, Word, PowerPoint, CSV/JSON, images via OCR, and caption/transcript files (`.srt`, `.vtt`) can be indexed. Image OCR needs Tesseract installed locally.
- **User memory and private routing:** the **Advanced** panel stores user-editable preferences separately from chat history. Privacy mode routes grounded responses through the local Ollama model rather than Groq.
- **Controlled agents:** agent plans are inspectable. The included calculator requires explicit browser approval and only evaluates safe numeric expressions; it has no shell, filesystem, or network execution ability.
- **Knowledge graph and workspaces:** indexing extracts a lightweight entity graph. The workspace API supports owner/editor/viewer membership and comments; it is ready for richer shared-document UI flows.
- **Source-trust information:** assistant replies explain the selected route, report citation verification status, and show possible source-conflict warnings.

Run the evaluation suite with:

```powershell
.\.venv\Scripts\python.exe -m pytest tests -q
```

## Backend Setup

The main backend reads configuration from `backend/config.py`, uses a local JSON store in `backend/database.py`, loads persisted model artifacts from `model/`, and serves chat responses through `/api/chat`. ChromaDB is the separate persistent vector store for RAG documents.

Required environment variables are optional for local development:

```env
FLASK_ENV=development
FLASK_DEBUG=1
```

## Frontend Setup

The frontend uses React 19 and Vite 8. It asks the backend for a locally persisted session, posts user messages to the backend, and displays the custom model response with metadata such as engine, confidence, and intent.

Useful scripts:

```bash
npm run dev
npm run build
npm run lint
npm run preview
```

## Custom Model Training

The custom model is trained from `data/intents.json` using `train_model.py`.

Training pipeline:

1. Load intents JSON.
2. Preprocess patterns.
3. Fit TF-IDF features.
4. Train Logistic Regression.
5. Save model artifacts to `model/`.

To add your own behavior, update the intents file with new patterns and responses, then rerun training.

## Ollama Setup

Install Ollama and pull the model configured in `.env`:

```bash
ollama pull llama3.2:3b
ollama serve
```

The default local configuration is:

```powershell
$env:OLLAMA_MODEL = "llama3.2:3b"
$env:OLLAMA_HOST = "http://127.0.0.1:11434"
```

The app only generates assistant replies through Ollama. If Ollama is offline or the model is missing, the UI shows the local model status instead of falling back to a cloud service.

## API

### GET `/api/session`

Creates or returns the current locally persisted chat session. The backend stores the session id in an HTTP-only cookie and returns saved history from the local store.

### POST `/api/session`

Clears the current local session and creates a fresh chat session.

### DELETE `/api/session`

Clears the current local session without creating a replacement session.

### POST `/api/chat`

Request:

```json
{
  "session_id": "optional-session-id",
  "message": "Explain Python decorators",
  "mode": "balanced",
  "temperature": 0.45
}
```

Response:

```json
{
  "response": "Assistant response...",
  "intent": "programming",
  "confidence": 0.76,
  "understood": true,
  "engine": "local_llm",
  "model": "llama3.2:3b",
  "session_id": "..."
}
```

### GET `/api/health`

Returns backend status, model availability, session count, and local LLM status.

## Local Storage Layout

`backend/local_store.json` is created automatically and stores:

- accounts
- authenticated chat sessions
- conversation history
- optional intent and model metadata

ChromaDB stores document embeddings separately under the configured RAG persistence directory.

## Troubleshooting

### Backend does not respond

- Confirm the backend is running on port 5000.
- Check the console for local-storage or model-load errors.
- Verify `torch`, `flask-cors`, and `flask-socketio` are installed in the workspace venv.

### Frontend shows CORS or fetch errors

- Start the backend first.
- Make sure the frontend is calling `http://localhost:5000/api/chat`.
- Confirm `/api/chat` returns `Access-Control-Allow-Origin` for `http://localhost:5173`.

### Model training fails

- Ensure `data/intents.json` is valid JSON.
- Confirm the `model/` directory is writable.
- Retrain after every intents update.

### Ollama is offline

- Start Ollama.
- Pull the model configured in `OLLAMA_MODEL`.
- Confirm `OLLAMA_HOST` points to `http://127.0.0.1:11434`.
