# Nexus - Local AI Chatbot

This repository contains a private chatbot stack with a Flask + Socket.IO backend, a React 19 + Vite 8 frontend, an Ollama-only local LLM engine, and a separate FastAPI Retrieval-Augmented Generation (RAG) service. Application data is persisted in a local JSON store, and **ChromaDB is the vector database** for RAG document embeddings and retrieval.

## Overview

- The default chat engine is **Ollama** running on your machine; no cloud API key is needed for normal chat.
- Accounts, session ids, and conversation history are persisted in `backend/local_store.json` - no SQL server is required.
- A custom intent classifier (TF-IDF + Logistic Regression) supplies intent metadata; assistant replies are generated by Ollama.
- The RAG API runs independently at `http://127.0.0.1:8000`, uses Groq `llama-3.3-70b-versatile` for generation (with a local Ollama fallback when no key is set), and returns ranked source citations.
- **ChromaDB** is the persistent vector store for RAG retrieval. Every document index is namespaced per account or workspace, and the health endpoint confirms Chroma connectivity.
- Login tokens are JWTs (HS256) that can be **revoked on logout** via a shared file-backed blacklist; both the Flask and RAG services check it.

## Features

### Chat experience
- Real-time chat UI with a glass-panel layout (HTTP and WebSocket channels).
- Custom intent model with TF-IDF + Logistic Regression; a separate Ollama integration drives **balanced**, **precise**, and **creative** response modes.
- **Undo / branching snapshots:** after any change the previous chat state is captured; press `Ctrl+Z` (or the header/toolbar button) to restore the last change.
- **Edit and resend** your own messages and **regenerate** the last assistant reply.
- **Message reactions:** hover a message to add emoji reactions; they persist per user in `localStorage`.
- **Pin chats:** bookmark conversations in the sidebar; pinned chats are sorted to the top.
- **Auto-titles:** new conversations are titled automatically from the first user message.
- **In-conversation search:** a search bar inside the transcript highlights matches and jumps through them.
- **Markdown export:** download any conversation as a Markdown file (`FileDown` button or command palette).
- **Chat sharing:** publish a read-only snapshot of the current conversation behind a public link (`Share` button). Anyone with the link can view it without logging in; the snapshot is fixed at creation and the owner can revoke the link at any time from the same dialog.
- **Command palette (`Ctrl+K`):** jump to settings, export, undo, and more; `Esc` closes open panels/preview.
- **Voice & language pickers:** browser speech-to-text (STT) with a selectable language, and text-to-speech (TTS) with a selectable voice for reading replies aloud.
- **Image paste:** paste a screenshot into the composer to see an inline preview; the image is sent along and auto-described by an Ollama vision model.
- **Theme + PWA:** light/dark themes, mobile-responsive layout, installable as a PWA (offline service worker caches only the app shell).
- **PIN lock / auto-lock:** set a PIN in Settings; the workspace locks on idle (default 5 min), on tab switch/hidden, or instantly via *Lock now*.

### RAG
- **Query rewriting:** brief multi-turn follow-ups are rewritten into standalone retrieval queries using Groq (or the local Ollama model as fallback) when `RAG_QUERY_REWRITE=true`.
- **Hybrid retrieval:** semantic Chroma search is fused with BM25 keyword scoring (`RAG_HYBRID_LEXICAL_WEIGHT`); an optional cross-encoder **re-ranker** can be enabled on top.
- **Multimodal knowledge:** PDFs, Word, PowerPoint, CSV/JSON, images via OCR (Tesseract must be installed and on `PATH`), caption/transcript files (`.srt`, `.vtt`), and pasted images can be indexed.
- **User memory and private routing:** the Advanced panel stores user-editable preferences separately from chat history. Privacy mode routes grounded responses through the local Ollama model instead of Groq.
- **Controlled agents:** agent plans are inspectable. The included calculator requires explicit browser approval and only evaluates safe numeric expressions; it has no shell, filesystem, or network access.
- **Workspaces:** owner/editor/viewer membership, shared indexes, comments, and presence tracking.
- **Source-trust information:** assistant replies explain the selected route, report citation verification status, and flag possible source conflicts.
- **Retention:** documents can expire on a schedule and are cleaned up automatically on listing.
- **Prompt-injection filtering**, citation verification, source-conflict detection, and a multi-language `respond in <language>` option.

### Admin dashboard (RAG)
- Charts: 14-day answer-volume and average-latency timeline beside the audit table.
- **Chroma stats viewer:** collection names, chunk counts, and total index size.
- **Rate-limit / quota panel:** per-account active-request usage bars against the configured quota.
- **Anomaly alerts:** automatic detection of answer-volume spikes and storage growth beyond a threshold, with the historical storage trend shown.
- **Weak-query suggestions:** low-confidence retrieval queries are surfaced in analytics for revisiting.
- Live retrieval evaluation per account (`/api/admin/evaluation/run`).

### Safety & operations
- **JWT revocation:** logout revokes the token's `jti` (stored with its expiry in `.jwt_blacklist.json`); revoked tokens are rejected by both services until expiry.
- **`.env` placeholder sanity check:** startup warns (and `/api/health.config_warnings` reports) when `SECRET_KEY` or `GROQ_API_KEY` still hold template values.
- **Fire-and-forget admin telemetry:** daily request metrics and a self-seeding storage-growth history are kept under `admin_data/`.
- **Backup & restore:** download a JSON backup of all preferences plus the current account's chat history, and restore it later.
- **Ollama model switcher:** pick which local model answers (`/api/local/models`), persisted at runtime in `.active_llm_model`.
- A 32-case retrieval/robustness/security evaluation suite plus a **66-test pytest suite**.

## Quick Start

### 1. Install Python dependencies

```powershell
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
```

### 2. Configure `.env`

Copy `.env.example` to `.env` and set a random `SECRET_KEY` (a placeholder value logs a warning on startup and in `GET /api/health`):

```powershell
Copy-Item .env.example .env
```

Generate a secure key with:
```powershell
.\.venv\Scripts\python.exe -c "import secrets; print(secrets.token_hex(32))"
```

### 3. Train the intent classifier

```powershell
.\.venv\Scripts\python.exe train_model.py
```

Artifacts are written to `model/`.

### 4. Start the Flask backend

```powershell
.\.venv\Scripts\python.exe app.py
```

or the lighter wrapper:

```powershell
.\.venv\Scripts\python.exe serve_local.py
```

The Flask-served UI is at `http://localhost:5000`.

### 5. Start the React frontend

```powershell
cd frontend
npm install
npm run dev
```

Open `http://localhost:5173` in the browser.

Alternatively, `run_local.bat` starts both the backend and the frontend in separate windows; `run_app.bat` starts only the backend.

## Authentication

Authentication is stateless and JWT-based (HS256, `PyJWT`). Logging in or registering mints an access token carrying `sub`, `email`, `is_admin`, `iat`, `exp`, `aud = ai_chatbot:api`, and a unique `jti` claim, signed with `SECRET_KEY`. The token is returned in the JSON response and stored in an HTTP-only `access_token` cookie, so browser clients authenticate automatically while API clients can use `Authorization: Bearer <token>`.

Each issued `jti` is recorded in `.jwt_blacklist.json` the moment the account logs out, so the token is rejected immediately by both the Flask and RAG services rather than waiting for expiry. Expired entries are pruned automatically.

Register once, then log in:

```powershell
# Register
Invoke-RestMethod -Method POST http://localhost:5000/api/auth/register -ContentType 'application/json' `
  -Body '{"email":"you@example.com","password":"password123"}'

# Login
Invoke-RestMethod -Method POST http://localhost:5000/api/auth/login -ContentType 'application/json' `
  -Body '{"email":"you@example.com","password":"password123"}'
```

Both responses return the authenticated user plus `access_token` and `expires_in`. Protected endpoints (`/api/session`, `/api/chat`, `/api/local/models`) accept the JWT via the cookie or as a bearer token; token lifetime defaults to 24 hours and is configurable with `JWT_ACCESS_TOKEN_MINUTES`.

### Refresh, logout, and revocation

- `POST /api/auth/refresh` - issues a fresh access token for the current account (and resets the cookie).
- `POST /api/auth/logout` - revokes the token's `jti` in the blacklist, clears the access-token cookie, and returns `{"status": "logged_out"}`.

### RAG token

The RAG service is separate and validates the same HS256 JWT (same `SECRET_KEY` and `aud = ai_chatbot:api`). Logged-in clients obtain one from the Flask backend and send it as a bearer token:

```powershell
$token = (Invoke-RestMethod -Method POST http://localhost:5000/api/auth/rag-token).token
$headers = @{ Authorization = "Bearer $token" }
```

Use `$headers` on every RAG call below. Set `RAG_ADMIN_EMAILS` in `.env` to grant an account admin access.

## ai_chatbot RAG API

The RAG service runs independently of the Flask chatbot, allowing the retrieval stack to be evaluated and run on its own.

### Start the RAG API

1. Start Ollama, then pull the vision model used for pasted-image captions (optional):

```powershell
ollama pull llava
```

2. Add a Groq key to `.env` for cloud generation, or leave it blank to fall back to the local Ollama model:

```env
GROQ_API_KEY=your-key   # optional; blank falls back to Ollama
```

3. Start the API:

```powershell
.\.venv\Scripts\uvicorn.exe rag_api:app --reload --port 8000
```

4. Verify Chroma is connected:

```powershell
Invoke-RestMethod http://127.0.0.1:8000/api/health
```

The status reports the embedding model, generator model, chunk size/overlap, top-k, and whether Chroma connectivity and the query features are ready.

### Add and index your documents

Documents are stored per account under `user_documents/<account>/`, encrypted at rest. Upload one or more files, then rebuild the index:

```powershell
$headers = "Authorization: Bearer $token"
curl.exe -X POST http://127.0.0.1:8000/api/documents/upload -H $headers -F "files=@handbook.pdf"

Invoke-RestMethod -Method POST http://127.0.0.1:8000/api/documents/ingest -Headers @{ Authorization = "Bearer $token" }
```

Re-running `POST /api/documents/ingest` rebuilds the account's index from scratch, preventing stale chunks after document updates. Indexing extracts a lightweight entity graph that powers the knowledge-graph endpoint.

### Ask questions

```powershell
Invoke-RestMethod -Method POST http://127.0.0.1:8000/api/chat `
  -Headers $headers -ContentType 'application/json' `
  -Body '{"message":"What are the hostel rules?"}'
```

Responses include an ordered `citations` array with the source name, chunk id, excerpt, relevance score, and page. The browser UI uses the streamed variant `POST /api/chat/stream` (SSE) so long answers render progressively and can be cancelled.

### RAG features

- **Query rewriting:** with `RAG_QUERY_REWRITE=true`, brief follow-ups are rewritten into standalone retrieval queries by Groq (or the local Ollama model when no Groq key is set); lexical fallback when no generator is reachable.
- **Hybrid retrieval:** semantic Chroma search is fused with BM25 keyword scores (`RAG_HYBRID_LEXICAL_WEIGHT`, default 0.35); set to 0 for vector-only. An optional cross-encoder **re-ranker** (`RAG_RERANK_ENABLED=true`) reorders the final candidates.
- **Multimodal knowledge:** PDFs, Word, PowerPoint, CSV/JSON, images via OCR (Tesseract must be installed and on `PATH`), caption/transcript files (`.srt`, `.vtt`), and **pasted images** (auto-captioned by an Ollama vision model) can be indexed or asked about.
- **User memory and private routing:** the Advanced panel stores user-editable preferences separately from chat history. Privacy mode routes grounded responses through the local Ollama model instead of Groq.
- **Controlled agents:** agent plans are inspectable. The included calculator requires explicit browser approval and only evaluates safe numeric expressions; it has no shell, filesystem, or network access.
- **Workspaces:** owner/editor/viewer membership, shared indexes, comments, and presence tracking, ready for richer shared-document UI flows.
- **Source-trust information:** assistant replies explain the selected route, report citation verification status, and flag possible source conflicts.
- **Retention:** documents can expire on a schedule and are cleaned up automatically on listing.
- **Weak-query analytics:** retrievals that fall below the confidence threshold are surfaced as weak queries in admin metrics for revisiting.

## API - Flask Chatbot

### GET `/api/health`

Returns backend status, intent-model status, local LLM status, active session count, storage backends, and a `config_warnings` list for placeholder environment values.

### GET/POST/DELETE `/api/session` (login required)

Creates or returns the account's locally persisted chat session. The backend stores the session id in an HTTP-only cookie and returns saved history from `local_store.json`. `POST` clears the current session; `DELETE` clears it without replacing it.

### POST `/api/chat` (login required)

Request:

```json
{
  "session_id": "optional-session-id",
  "message": "Explain Python decorators",
  "mode": "balanced",
  "temperature": 0.45
}
```

Response:

```json
{
  "response": "Assistant response...",
  "intent": "programming",
  "confidence": 0.76,
  "understood": true,
  "engine": "local_llm",
  "model": "llama3.2:3b",
  "session_id": "..."
}
```

Response modes: `balanced` (temperature 0.45), `precise` (0.2), `creative` (0.75). Chat also works over WebSocket events (`join`, `message`, `reset`, `history`) served by Flask-SocketIO.

### GET/POST `/api/local/models` (login required)

- `GET` returns the Ollama server's `installed_models` and the currently chosen model.
- `POST` with `{"model": "llama3.2:3b"}` switches the active local model for all subsequent local-engine requests. The choice is persisted at runtime in `.active_llm_model` so it survives restarts and is reflected in the UI's Settings panel.

### Chat sharing

- `POST /api/shares` (login required) - create a public read-only link to the current chat session; snapshots up to 200 stored messages (user + assistant turns) at creation time. Returns `share.token`, `share.url` (`/share/<token>`), `title`, `created_at`, `message_count`.
- `GET /api/shares` (login required) - list the current account's share links.
- `DELETE /api/shares/<token>` (login required) - revoke a link; only the owning account may revoke it.
- `GET /api/share/<token>` (**no auth**) - public read-only snapshot: `title`, `created_at`, `message_count`, `messages`.
- `GET /share/<token>` - serves the SPA shell for the read-only public view.

### Auth

- `POST /api/auth/register` - create an account (email + password, min 8 chars); returns a JWT and sets the `access_token` cookie.
- `POST /api/auth/login` - log in; returns a JWT and sets the cookie.
- `POST /api/auth/logout` - revoke the JWT `jti`, clear the access-token cookie.
- `GET /api/auth/me` - current account from JWT/cookie/session or `401`.
- `POST /api/auth/refresh` - issue a fresh JWT for the current account.
- `POST /api/auth/rag-token` - issue a JWT bearer token for the RAG service (login required).

## Frontend

- **Settings panel** groups every preference: theme, STT language, TTS voice, PIN lock + auto-lock timeout (minutes or "Never"), the **Ollama local model** picker (shown only when the local engine is active), and a **Backup & restore** block with *Download backup* / *Restore* buttons.
- **Backup file** (`ai-chatbot-backup-<date>.json`) contains all `ai_chatbot_*` preferences and the current account's chat history; restoring validates the payload before reloading it from `localStorage`.
- **Keyboard shortcuts:** `Ctrl+K` command palette, `Ctrl+Z` undo (when snapshots exist), `Ctrl+Enter` send while typing, `Esc` close panels.
- The chat composer supports text attachments, pasted-image previews, voice input (STT with language picker), and streamed RAG answers toggled per conversation.

## Storage Layout

- `backend/local_store.json` - created automatically; stores accounts, authenticated chat sessions, conversation history, public share links, and optional intent/model metadata. Written atomically (temp file + replace).
- `.jwt_blacklist.json` - file-backed registry of revoked JWT `jti` values with their expiry; expired entries are pruned on write.
- `.active_llm_model` - the last model selected via the local model switcher.
- `chroma_db/` - ChromaDB persisted vectors. One collection per namespace is created as `<CHROMA_COLLECTION>_<namespace>` (e.g. `ai_chatbot_knowledge_base_1` per account, `..._workspace_<id>` for workspaces).
- `user_documents/<account>/` - encrypted uploads (Fernet key derived from `SECRET_KEY`), indexed versions, retention rules, audit log, metrics, and feedback.
- `knowledge_graph/<namespace>/` and `workspaces/` - lightweight entity graphs and workspace definitions (created at runtime, gitignored).
- `admin_data/` - admin telemetry: daily request metrics and a self-seeding storage-growth history used by the anomaly alerts.

Neither the JSON store nor the Chroma collections are shared between accounts: retrieval is always namespaced to the requesting account or workspace.

## Tests

Run the pytest suite (66 tests) with:

```powershell
.\.venv\Scripts\python.exe -m pytest tests -q
```

The suite covers the chat/auth/revocation flow (`test_auth_jwt.py` includes token lifetime, jti claims, and blacklist revocation), conversation sharing (`test_chat_sharing.py` covers create/list/public-get/revoke, owner-only deletion, and auth enforcement), the RAG admin endpoints (quotas, anomalies, Chroma stats), RAG JWT auth through the FastAPI `TestClient` (`test_rag_auth_api.py`), the Ollama model switcher (`test_local_llm.py`), the `.env` placeholder check (`test_placeholder_check.py`), and the retrieval/quality paths (`test_rag_quality.py`).

The RAG evaluation suite (`rag/evaluation.py`, 32 cases) covers retrieval, robustness, chunk boundaries, document updates, contradictory documents, hallucinations, and security jailbreaks. Admin users can run retrieval evaluation live per account from the admin panel, and the tests exercise the guard checks.

## Troubleshooting

### Backend does not respond

- Confirm the backend is running on port 5000.
- Check the console for local-store, model-load, or **configuration warnings** (placeholder `SECRET_KEY` / `GROQ_API_KEY`).
- Account/auth errors mean you need to register/login first - the chat endpoints require authentication.
- If requests show `401` right after login, the token may have been revoked - log in again to receive a fresh one.

### Frontend shows CORS or fetch errors

- Start the backend first.
- Make sure the frontend is calling `http://localhost:5000/api/chat`.
- The RAG UI calls `http://127.0.0.1:8000`; start `uvicorn rag_api:app --port 8000` before using RAG features.

### RAG returns `401` on chat endpoints

The RAG API only accepts bearer tokens issued by `POST /api/auth/rag-token` (they expire after 1 hour and are revoked on logout). Request a fresh token after logging in.

### Model training fails

- Ensure `data/intents.json` is valid JSON.
- Confirm the `model/` directory is writable.
- Retrain after every intents update.

### Ollama is offline

- Start Ollama.
- Pull the model configured in `OLLAMA_MODEL`.
- Confirm `OLLAMA_HOST` points to `http://127.0.0.1:11434`.
- Pasting images requires the vision model in `OLLAMA_VISION_MODEL` (`ollama pull llava`); without it, images send a polite "could not be described" placeholder instead of failing.

### Image documents are not indexed

- Install the Tesseract desktop application and make sure it is on `PATH`, then re-index.

### RAG answers say "not enough support"

- The account's index is empty or below the confidence threshold. Upload documents, then run `POST /api/documents/ingest`. Check `GET /api/admin/chroma` and `/api/admin/metrics` for index size and weak queries.

## Security Notes

- All chat data stays local by default; no cloud API keys are required unless you enable Groq-based RAG generation.
- Login tokens carry a unique `jti` and are revoked on logout; the blacklist is checked by both the Flask and RAG services, so logged-out tokens are rejected immediately.
- Uploaded documents are encrypted at rest with a key derived from `SECRET_KEY` - always set a real, random `SECRET_KEY` (a placeholder value triggers a startup/config-warning notice).
- The RAG system treats retrieved documents as untrusted reference material and filters prompt-injection patterns before they reach the model.
- Agent tools (calculator) evaluate only safe numeric expressions and require explicit browser approval.
